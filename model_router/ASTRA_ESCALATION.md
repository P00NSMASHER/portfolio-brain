# Governed Astra escalation (disabled pilot)

Astra is reserved for a specific high consequence, unresolved decision with a reference to an insufficient or blocked cheaper route. Deterministic work, routine reporting, coding, and first-pass analysis remain on existing routes. The checked-in policy, kill switch and model registry keep this path disabled. No workflow invokes it automatically.

The caller supplies a sanitized reference-only context pack: project IDs, source commit SHAs, a context SHA-256 digest, evidence references, the cheaper-route receipt and its outcome, the decision's proposed outcome reference, the builder's independence group, and token, cost, authority and effort limits. The caller must verify referenced evidence; admission checks shape and bounds, not truth of external references. Aim for 8,000–20,000 useful input tokens; 40,000 is the hard maximum. Never put secrets, credentials or private raw content in the provider input. Use only `PUBLIC` or `SANITIZED`.

`admit_escalation` rejects routine, low consequence, privileged, unsanitized, unreviewed-effort or over-budget work. An admitted request stays Tier 3 and selects only Astra, with an independence group different from the builder. `execute_openai(..., astra_candidate=...)` checks admission again before reserving funds. It forbids automatic Astra retries, uses the existing durable cost governor and produces the ordinary model call receipt. A receipt grants no authority or evidence promotion. Unknown provider outcomes conservatively consume their reservation. If routing or the cost reservation fails, there is no provider call; the ordinary cheaper path remains the fallback.

The portfolio ceiling stays $10 per UTC day. Astra has a stricter provider/model ceiling of two calls and $2.50 per UTC day; each request is limited to $1.25, 40,000 input and 12,000 output tokens. Standard pricing in the registry is $10/$50 per million input/output tokens. Allowed reasoning effort is medium, or high with a specific decision need. Provider tools, deployment, merging, payments, trading and credential authority are outside this path. Runtime opt-in requires all three gates: reviewed policy enablement, clearing `ASTRA_KILL_SWITCH.json`, and `PORTFOLIO_ASTRA_ENABLED=1`. Enabling also requires updating the checked-in validator in a reviewed change. Leave it disabled until a candidate and independent review plan are approved.

Log only IDs, hashes, usage, cost and receipt references in durable state. Compare a pilot against a cheaper-route baseline on verified downstream outcomes, not model prose or activity. Require at least three independently verified outcomes before adapting routing. Stop the pilot for cost overruns, false confidence, missing receipts, privacy leaks or any attempt to widen authority. A kill-switch flip stops new admissions; it does not retroactively cancel a call already in flight.
