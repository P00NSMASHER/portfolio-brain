# Owner decisions

A Brain cycle gathers evidence. “Continue” asks for up to three changed decisions. An explicit chat instruction naming a problem and the authorized action is required before the owner session opens a repair PR, enrolls it in auto-merge, or merges it. Preserve an existing PR and coordinate with its recorded owner. An issue, label, CI result, old acceptance fixture or ledger edit cannot authorize a writer.

The protected `repair/OWNER_DECISIONS.json` file records each registered target, existing PR, decision, owner, evidence and acceptance. Record the actual chat reference and approved scope when a decision changes. The durable `owner_decision` table in the existing Brain state transaction retains the latest evidence under a stable problem ID. `decisions.json` in the original core artifact emits at most three changes per cycle and keeps additional changes pending. The same packet is committed as `owner-decisions.json` on `brain-state-v2` in the transaction that advances the SQLite state. If an artifact is missing, recover the packet at the exact state commit for the original run and source. A later branch tip can contain a different packet. An unchanged blocked target produces no new decision. A changed target head alone does not count as delivery.
